## Refreshing

```sh
make sync-spec PHASETWO_KEYCLOAK=/path/to/phasetwo-keycloak   # rebuild, copy, diff
make generate                                                 # regenerate internal/client
```

`sync-spec` runs `mvn -pl phasetwo-module -am -DskipTests process-classes` in the checkout you
point it at, so it needs a JDK and Maven. It copies the file and prints a diff; updating the pin
above is a deliberate edit.

## Known spec limitations the client works around

- **No `operationId` for error responses.** The spec documents only success codes, so the client
  maps non-2xx by status code rather than by schema.
- **`ClusterCreationResult` is a flat five-field union**, not a `oneOf`. The client branches on
  which fields are populated; see `cluster.go`.
- **`WellKnown` and `WellKnownFile` carry no field descriptions or `required` list** — they
  document themselves with javadoc, which the OpenAPI scanner does not read. Not used by this
  provider.
